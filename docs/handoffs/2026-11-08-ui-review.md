## Lessons (these will recur if forgotten)

- **RTL must be looked at in the real app, in Hebrew.** A story with `dir="rtl"` set on an inner element or after load does not reproduce what the document-level attribute does. React Native Web's `Switch` looked correct in Storybook and left its track in the running app, which the user found. The toggle is now `ModeSwitch`, and `provider-access-smoke` measures it in Hebrew. The original bug was never reproduced locally: the diagnosis rests on the user's screenshot.
- **`ProviderAccess` renders nothing when its screen loses focus, so business screens unmount on every departure.** It is deliberate: private state does not linger. It looks like a navigation bug: `push` and `dismissTo` do not preserve the agenda's date, and Back from Account shows today. Do not chase it in the router.
- **Leaving provider mode must use `router.dismissTo('/')`.** `replace` left the customer on a stale Home two screens deep. The same call reaches the agenda from the footer without piling up screens, and opens it when none is in the stack.
- **Selecting a business clears the drafts**, so `openManualBooking` selects first and only then opens the form. Reversing them closes the form after a reload on Account.
- **`testID="language-he"` means "switches to Hebrew".** The control names the other language, so the id exists only while the current language is English. A smoke clicking it on a Hebrew page times out.
- **Removing a button can remove the path that reset state.** The footer's Add appointment bypassed the hook's `update`, which cleared the form's message and review. QA found the stale review. `openManualBooking` now leaves a form in progress alone and starts empty otherwise.
- **`actionHeight` is no longer a touch target.** It is 36 and only `CompactControl` makes up the difference by overhang. A text field using it shrank to about 40px, so inputs use `minTouchTarget`, and `Foundation.stories` measures one.
- **Browser runs here:** ports 3001/3002 were held by other servers, so the suite ran on a temporary copy of `web-smoke.mts` with 3001 replaced by 3917 and `VISIT_TEST_WEB_PORT=8917`. Re-export the web build after any app change, or the suite tests old code.
- **Storybook cannot bundle `expo-router`, `expo-crypto` or `react-native-svg`.** Icons are drawn from Views for that reason and because the web build ships no icon font. Screens using the router are covered by smokes, not stories.

## Debt

- **A customer cannot erase an archived provider**, and no account-deletion path exists. A row links a person to a business, which can be sensitive for a clinic, and it blocks a hard delete of that business. The user chose to leave this for now. Close it before going live.
- **Disabled SMS and WhatsApp icons** on appointment details are still shown. Whether to hide them until delivery exists was never decided.
- **A newly granted business shows its toggle at the next screen change**, not at once. **A failed account load hides the toggle**; retry is in Account.
- **Account has no heading** after the title was removed, at the user's request. Screen readers start at "Sign-in methods", and a guest has no heading there at all.
- **`test:vis11` was not run.** Its drawer block was removed. Native builds were exported but not run on a device, so `ModeSwitch`, the footer and the toast have not been seen on iOS or Android.
- **Account has no visible Back control**, only the browser or system gesture; the footer still leaves it. The appointment details page has one.
- **`additionalCount` in `/upcoming` has no screen reading it** since Home lists today's appointments. Its API tests remain.
- **The provider application still says pilot businesses use Israeli time** (`account.timezoneHint`). It explains a rule rather than a display, so it stayed when the time-zone sentence was removed; the user has not looked at it.
- **`MAX_TODAY_APPOINTMENTS` has no test** of the cap, and no API test creates several appointments today; `onLocalToday` has a pure test.
- **API tests log dotenv loading `../../.env`** with 0 values injected. It predates this work and conflicts with the rule that tests never read `.env`.
- **`apps/api/test/booking-guard.test.ts:116` failed once with 409** and passed on rerun with no API change. Not investigated.
